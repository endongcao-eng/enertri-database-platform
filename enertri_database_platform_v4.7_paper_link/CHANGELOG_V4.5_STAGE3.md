# EnerTri V4.5 Stage 3 — 项目需求与科研人才智能匹配

发布日期：2026-08-28

## 本阶段目标

把 V4.3 的科研知识/能力标准库与 V4.4 的学生证据画像真正用于科研项目选人：老师建立项目要求后，系统逐项计算学生是否满足，并进一步给出互补团队组合。

## 新增数据模型

- `research_projects`：科研项目需求模型；
- `project_capability_requirements`：项目能力要求，保存能力节点、要求等级、权重、关键项与说明；
- `project_knowledge_requirements`：项目明确知识要求，保存知识节点、要求等级、权重与关键项；
- Alembic revision：`v4_5_project_talent_matching`。

项目要求直接引用 V4.3 的 `capabilities` 与 `knowledge_nodes`，没有重复创建另一套标签体系。

## 新增能力

### 1. 项目需求能力模型

老师可建立一个项目，并明确：

- 所需科研能力；
- 每项能力要求等级（L0–L5）；
- 项目中的相对权重；
- 是否为关键要求；
- 可选的明确知识要求。

### 2. 可解释项目文本需求草案

`POST /api/project-matching/draft-requirements`

输入课题名称和说明后，系统使用可解释关键词规则生成能力/知识要求草案，并返回每个要求命中的关键词。草案不会直接成为硬性筛选条件，必须由老师确认后保存。

### 3. 学生智能匹配

`GET /api/project-matching/projects/{id}/matches`

匹配直接使用 V4.4 的个人科研画像：

- 能力满足度；
- 知识满足度；
- 证据可信度；
- 关键项缺口；
- 推荐理由；
- 主要短板；
- 每个项目要求的当前等级 / 目标等级 / 满足率。

当前默认模型：

- 明确知识要求存在时：能力 80% + 知识 20%；
- 证据可信度形成 90%–100% 的最终可信系数；
- 关键要求低于 65% 会产生额外缺口惩罚；
- 总分只用于排序，页面保留逐项解释。

### 4. 科研团队智能组队

`GET /api/project-matching/projects/{id}/teams?team_size=3`

团队不是个人分数相加。对于每一个项目要求，系统让团队中该项最强的成员承担，再重新计算项目覆盖度，同时返回：

- 团队总覆盖；
- 相比最佳个人的互补增益；
- 每名成员建议负责的能力模块；
- 团队仍未补齐的要求。

### 5. 隐私边界

由于人才匹配会横向比较多名学生画像，完整候选排名与团队推荐当前仅开放给管理员/教师侧角色；普通学生仍只能查看自己的科研画像。

## 演示项目与候选人

新增项目：`基于机器学习的材料热物性预测`。

为了验证组队互补而非单人排名，新增三个不同能力结构的演示学生：

- 林同学：材料机器学习与科研数据建模；
- 周同学：微纳热输运与数值模拟；
- 王同学：实验数据分析与焊接缺陷机理。

同时在标准资源中新增 `材料热物性机器学习预测任务`，作为可核验项目任务证据。
