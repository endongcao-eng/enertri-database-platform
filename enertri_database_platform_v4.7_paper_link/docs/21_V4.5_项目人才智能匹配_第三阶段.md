# V4.5 第三阶段：项目需求能力模型与科研人才智能匹配

## 1. 数据链

```text
V4.3 标准知识 / 标准能力
          ↓
V4.4 学生个人证据画像
          ↓
V4.5 项目能力 / 知识要求
          ↓
个人匹配 + 缺口解释 + 互补团队
```

## 2. 项目要求不是文本标签

项目能力要求保存在 `project_capability_requirements`，知识要求保存在 `project_knowledge_requirements`。二者分别使用外键引用现有能力和知识标准节点，因此学生画像与项目需求拥有同一坐标系。

每一项要求至少包含：目标等级、权重、是否关键以及老师说明。

## 3. 个人匹配

学生的当前能力等级 = V4.4 画像能力分 / 20。项目要求满足率为 `min(当前等级 / 要求等级, 1)`。

系统进一步加入证据可信度和关键项缺口惩罚，最终输出排序分，但不隐藏原始满足率。

## 4. 团队推荐

团队推荐按“每个要求由团队中该项满足率最高成员承担”计算覆盖，不进行简单个人分数求和。系统将每个能力要求分配给最适合成员，并展示团队仍存在的缺口。

## 5. API

- `GET /api/project-matching/projects`
- `GET /api/project-matching/projects/{id}`
- `POST /api/project-matching/draft-requirements`
- `POST /api/project-matching/projects`
- `PUT /api/project-matching/projects/{id}`
- `GET /api/project-matching/projects/{id}/matches`
- `GET /api/project-matching/projects/{id}/teams?team_size=2|3|4`

## 6. 权限

项目本身可由登录用户查看；跨学生的人才匹配和团队推荐目前仅教师/管理员侧可访问，防止普通学生横向读取其他学生画像。
