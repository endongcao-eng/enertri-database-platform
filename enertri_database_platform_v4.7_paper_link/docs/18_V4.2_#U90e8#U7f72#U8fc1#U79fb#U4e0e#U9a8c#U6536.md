# V4.2 部署、迁移与验收

## 推荐部署

生产环境使用 PostgreSQL。Web 层可继续使用多个 Gunicorn Worker，因为 V4.2 Web 进程不再创建任务线程池、不执行任务恢复、不执行默认数据初始化。长任务由独立 `worker` 服务执行。

Docker Compose：

`db -> init -> backend + worker -> caddy`

`init` 是一次性容器，成功完成 Alembic、默认数据、过期租约恢复和审计后退出；`backend` 与 `worker` 才开始运行。

## 非 Docker 开发

首次/升级：

```bash
cd backend
cp .env.example .env
python scripts/bootstrap.py
```

分别启动：

```bash
uvicorn app.main:app --reload
python scripts/task_worker.py
```

仅测试环境可设置 `TASK_EXECUTION_MODE=inline` 让任务同步执行；生产必须保持 `database_worker`。

## 数据库升级

V4.1 → V4.2：

```bash
python scripts/migrate.py upgrade head
```

目标 revision：`v4_2_knowledge_system`。

对旧的未受 Alembic 管理数据库，系统先输出 baseline 结构报告。任何关键字段、类型、约束或索引不匹配都会拒绝 stamp。生产环境必须先备份，再临时设置 `V4_BASELINE_CONFIRM=I_HAVE_VERIFIED_V4_0_BACKUP`。
