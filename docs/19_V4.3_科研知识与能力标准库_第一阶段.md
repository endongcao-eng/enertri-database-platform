# V4.3 第一阶段：科研知识与能力标准库

## 1. 第一阶段边界

本阶段解决“标准是什么”，不解决“某个学生到底是多少分”。系统先让所有后续分析共享同一套知识和能力定义，避免项目匹配、选课推荐、教师补知识分别建立互不兼容的标签体系。

标准主链路：

```text
课程 / 专业书 / 项目任务
        ↓
标准知识节点
        ↓
科研能力节点
        ↓
第二阶段个人证据画像
        ↓
项目找人 / 选课 / 科研方向 Gap / 团队组队
```

## 2. 为什么不直接用标签

“学过传热学”“读过专业书”“参加过项目”不能直接等价为一个能力。第一阶段把这些原始来源拆成可追溯关系：

- 资源覆盖哪些知识；
- 覆盖到什么等级；
- 这类来源作为证据有多强；
- 哪些知识是某项能力的必要基础；
- 一个项目任务能够直接贡献哪些实践能力。

第二阶段再把学生个人成绩、读书完成度、项目独立度、导师评价等乘到这些标准关系上。

## 3. 数据结构

### 3.1 knowledge_nodes

标准知识节点。字段包括 code、中英文名、领域、节点类型、描述、等级尺度、状态，以及 `linked_term_id`。

`linked_term_id` 是原术语库与新知识体系之间的桥：术语负责规范命名和解释，知识节点负责在科研体系中建立先修、能力与学习来源关系。

### 3.2 knowledge_relations

支持先修、组成、相关和使能四类关系，可形成可计算的知识网络。

### 3.3 capabilities

科研能力节点按理论、方法、计算、实验、科研、表达、项目七类组织，并保留 1–5 级 rubric。

### 3.4 capability_knowledge_links

明确一项能力依赖哪些知识、要求等级和权重。例如“数值建模与求解”需要偏微分方程，并由有限差分、有限元等方法知识支撑。

### 3.5 learning_resources

统一三类标准输入：`course`、`book`、`project_task`。后续还可以扩展为论文训练、仪器培训、竞赛等，但第一阶段先固定这三类，避免模型过度扩张。

### 3.6 resource_knowledge_links / resource_capability_links

分别描述来源到知识、来源到能力的映射。除了等级和权重，还保存 evidence_strength，使“读书”和“真实项目任务”在后续个人证据计算中不会被当作同等强度。

## 4. 映射演算

`POST /api/capability-standards/simulate` 接受资源 ID 列表，聚合它们对知识和能力的标准贡献，并返回 trace。

当前聚合采用独立证据合并方式，避免简单把资源数量相加导致分数无限膨胀。返回值用于检查标准设计是否合理，不用于给学生定级。

## 5. 权限

- 普通登录用户：读取标准库、查看图谱、执行映射演算；
- 管理员 / system_admin：新增知识点、能力、资源和映射关系；
- 后续可增加“学科负责人/标准审核专家”工作流，本阶段未扩张角色体系。

## 6. 与第二阶段接口

第二阶段个人画像建议新增 Evidence 层：

```text
学生记录
├─ 课程成绩
├─ 读书进度 / 笔记 / 测验
├─ 项目任务与独立完成度
├─ 论文 / 模型 / 数据等成果
└─ 导师评价
        ↓
调用第一阶段标准映射
        ↓
个人知识掌握度 + 能力可信度 + 证据路径
```

这样项目匹配和选课推荐不会直接读取“自填能力”，而是读取可验证的个人证据画像。

## 7. 本阶段实际运行结果

fresh SQLite 验收库完成迁移：

```text
v4_0_baseline
→ v4_1_foundation
→ v4_2_knowledge_system
→ v4_3_capability_standard_library
```

默认标准库：15 个知识节点、8 个能力节点、6 个来源资源、64 条关系。

运行示例选中：传热学、Micro/Nanoscale Heat Transfer、微纳热输运数值模拟任务。

得到主要知识映射：微纳尺度传热 87.1、Python 科学计算 74.4、声子输运 71.3、热传导 63.6、对流换热 54.4。

得到主要能力映射：传热理论分析 79.7、Python 科研计算 77.1、数值建模与求解 73.6、科研数据分析 49.0、文献调研与证据综合 37.0。

浏览器运行预览保存在 `demo_outputs/v4_3_stage1_*.png`，运行数据保存在 `demo_outputs/v4_3_stage1_runtime_preview.json`。
