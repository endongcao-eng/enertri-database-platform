# V4.2 文献与论文知识系统

## 1. 多来源文献适配层

`publication_service.py` 定义统一 Provider 协议：`search_publications()`、`get_publication()`、`get_citations()`、`get_references()`、`get_author()`、`get_fulltext_link()`。当前内置 OpenAlex 和 Crossref；接口层不绑定具体来源。

统一文献记录保存 DOI、标题、作者、机构、摘要、关键词、期刊、年份、引用量、开放获取状态、更新时间；`publication_sources` 额外保留来源名、来源 ID、来源 URL 和原始 payload，以便审计和重新同步。

## 2. 文献去重

入库前执行多级匹配：

1. DOI 规范化后完全一致。
2. 标题规范化后完全一致。
3. 标题相似 + 第一作者相似。
4. 年份/期刊作为辅助信号。

同一文献的多个来源不会复制主记录，而是追加来源 provenance；前端显示“跨源已合并”。

## 3. 论文解析流水线

`paper_ingest` 任务由独立 Worker 执行：

文件安全校验 → 文本层检测/逐页解析 → 低文本页 OCR 兜底 → 标题/摘要/章节 → 表格 → 图片与图注 → 参考文献 → 页面分块 → 本地向量化 → 结构化阅读。

持久化层包括：`knowledge_documents`、`knowledge_pages`、`knowledge_tables`、`knowledge_figures`、`knowledge_chunks`。每个结构化事实尽量保存物理页码、章节和原文片段。问答检索同样返回证据，而不是只返回模型摘要。

V4.2 默认向量实现是无需外部服务的确定性本地哈希向量，目的是保证离线部署可完整跑通。`knowledge_chunks.embedding_json` 已将向量持久化与检索层解耦，后续可平滑替换为 pgvector + 专用 embedding 服务，而无需改变证据模型和问答 API。

## 4. 知识库策略

支持 `personal`、`group`、`project`、`enterprise`、`public_terms` 五个层级。每个知识库可配置：

- 是否允许团队成员检索；
- 是否允许 AI 使用；
- 是否允许导出；
- 是否保留原文。

论文上传还保留文件保密等级以及“是否允许外部 AI”标记。`restricted` 等高保密文件继续遵循文件层外发限制。

## 5. 论文问答

`POST /api/knowledge/documents/{id}/qa` 只基于已解析分块和结构化证据回答。返回字段包括 `answer`、`confidence` 和 `evidence[]`；每条 evidence 包含页码、章节、excerpt、相关度以及带 `#page=N` 的页码定位链接。

当检索不到可靠证据时，系统应返回“未在已解析原文中找到足够证据”，而不是补造参数或结论。

## 6. 当前边界

- OpenAlex/Crossref 在线检索需要部署环境可以访问对应服务；单一来源失败不会破坏统一文献库，接口返回每个来源的状态。
- OCR 默认 `OCR_LANG=eng`；中文扫描论文需要在镜像中安装对应 Tesseract 语言包并设置 `OCR_LANG`。
- 表格抽取优先处理具有明显文本/网格结构的 PDF；复杂跨页表、扫描表格仍可能需要后续专用表格模型。
- “可点击页码”定位到 PDF 物理页，若出版物印刷页码与物理页码不同，后续可增加页码映射层。
