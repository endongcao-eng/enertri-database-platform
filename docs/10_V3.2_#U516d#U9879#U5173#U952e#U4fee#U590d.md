# V3.2 六项关键修复说明

本版本针对上一轮审查中仍存在的六个关键问题进行修正。

## 1. 学生不能绕过审核

- 学生新建词条时，后端强制写入 `draft`。
- 学生编辑自己的草稿时，后端保留原审核状态、审核意见和推荐标记。
- 只有管理员审核接口可以将词条设为 `approved`。
- 非草稿词条不能重复提交审核。

## 2. 草稿和待审核内容不再公开

- 非管理员访问词条列表时只能请求 `approved`。
- `status=all/draft/submitted` 对非管理员返回 403。
- 未发布词条详情仅管理员或创建者本人可查看。
- 未发布文章列表与详情仅管理员可查看。

## 3. 测验答案不再提前发送

`GET /api/terms/{id}/quiz` 只返回：

- 题目
- 随机排序后的选项
- `quiz_token`

答案和解析保存在后端短期测验会话中，提交后才返回。

## 4. 成绩不能由客户端伪造

- `POST /api/me/progress/{term_id}` 已移除 `quiz_score`。
- 额外提交 `quiz_score` 会被 Pydantic 拒绝。
- 游客和登录用户统一调用测验提交接口，由服务器计算分数。
- 只有登录用户的服务端计算结果会写入最高分。

## 5. Excel 相关术语可以正式导入

导入改为两阶段：

1. 先创建全部新词条并分配 ID。
2. 再按相关术语字段建立关系。

支持使用中文、英文、俄文术语名称或词条 ID 匹配。无法匹配或匹配不唯一时会返回行号和警告，不会让整批导入失败。

## 6. “待上传”不再被当成视频路径

- Excel 标记“有视频”时，只保存 `has_video=true`，不创建伪造媒体路径。
- `待上传`、`待补充`、`暂无`、`none` 等历史占位值会被后端忽略。
- 前端会显示“视频文件待管理员上传”，不会渲染损坏的播放器。

## 验证结果

已完成 Python 与 JavaScript 语法检查，并通过端到端回归测试，覆盖：

- 学生创建与编辑时的审核状态保护
- 匿名访问草稿和未发布文章
- 测验答案隐藏与游客服务端判题
- `quiz_score` 伪造请求拒绝
- Excel 双向相关术语导入
- 有视频但无文件路径的展示行为
