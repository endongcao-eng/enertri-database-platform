# V4.2 阻断项修复与任务架构

## 1. 独立任务 Worker

V4.2 不再允许 Gunicorn Worker 自己持有线程池执行长任务。Web 只负责事务性地创建 `workspace_tasks(status=queued)`；独立 Worker 轮询 PostgreSQL 并通过事务和 `FOR UPDATE SKIP LOCKED` 原子抢占任务。

任务新增字段：`worker_id`、`attempt_count`、`heartbeat_at`、`lease_expires_at`、`last_claimed_at`、`timeout_seconds`。抢占时同时写入 Worker ID、尝试次数、租约与事件日志；执行期间父 Worker 周期性续租；子进程异常退出或超过超时时间会被标记失败。

`recover_expired_tasks()` 只处理租约已经过期的 `running` 任务，不会把另一个正常 Worker 正在执行的任务判为“服务重启中断”。`queued` 任务无需启动时重新提交：数据库本身就是待消费队列，只要 Worker 可用就会继续抢占。

Docker Compose 启动职责拆分：

1. `db`：PostgreSQL。
2. `init`：一次性 Alembic upgrade、默认数据初始化、过期租约恢复、临时文件清理、迁移审计。
3. `backend`：Gunicorn/FastAPI，可多 Worker，只处理 HTTP。
4. `worker`：独立任务进程，可按吞吐量横向扩容。

## 2. 系统管理员保护

角色修改接口现在先检查“目标账户原角色”，而不是只检查 payload：

- 非 `system_admin` 无法修改任何现有 `system_admin`。
- 非 `system_admin` 无法授予 `system_admin`。
- 最后一个有效 `system_admin` 无法被降级或停用。
- 当前操作者不能通过该接口停用自身。
- 修改 `system_admin` 或涉及系统管理员角色时必须提交 `confirmation=<目标用户名>`。
- 成功变更写入 `security.privileged_user.updated` 专用审计事件。

## 3. 接口层权限闭环

V4.2 将“查看”与“管理”彻底分离：

- 自己任务：`task.own.view` / `task.own.retry` / `task.own.cancel`。
- 他人任务：`task.other.view` 只允许查看；重试/取消必须有 `task.other.manage`。
- 文件下载：自己的文件需要 `file.own.download`；他人文件需要 `file.other.download`，不能由 `file.other.view` 替代。
- 角色变更：`user.role.manage`。
- 数据导出：`data.export`。

审稿专家默认可查看他人任务/文件用于审核，但不能重试、取消或下载他人文件。

## 4. 内容级文件校验

所有工作区上传先读取字节并执行：扩展名白名单、系统 MIME 检测（libmagic/file）、魔数、格式专用验证。

- PDF：`%PDF-` 魔数 + pypdf 可打开并读取页数。
- DOCX/PPTX/XLSX/ZIP：ZIP 可读、CRC、路径穿越、条目数量、压缩比、OOXML 必要目录/文件。
- 图片：Pillow `verify()` + 尺寸读取。
- 视频：ffprobe 必须成功且存在实际 video stream。
- JSON/XML/文本：解析/编码验证。

无效上传保存在 `quarantine/`，`workspace_files.parse_status=failed`，并记录 `detected_mime_type` 与 `validation_json`。论文/视频任务不会再把解析器错误降级成“成功+警告”。

## 5. 严格旧库 baseline

对“非空但没有 alembic_version”的数据库，V4.2 生成结构差异报告并严格比对 V4.0 指纹：关键表、必要字段、字段类型族、检查/唯一约束、索引、新版本特征字段。任一项不匹配立即拒绝自动 stamp。

生产环境即使结构完全匹配，也需要先备份和人工核验，再设置：

`V4_BASELINE_CONFIRM=I_HAVE_VERIFIED_V4_0_BACKUP`

升级完成后应移除该临时变量。
