# V4.4 第二阶段：学生科研能力个人证据画像

## 1. 目标

把第一阶段标准库转化为“某一个具体学生当前知道什么、能做什么、证据有多可信、还缺什么”的动态科研数字画像。

主链路：

```text
标准课程 / 专业书 / 项目任务
            ↓
学生个人证据
成绩 / 完成度 / 独立度 / 成果质量 / 导师评价
            ↓
证据有效度 + 核验可信度
            ↓
个人知识覆盖图
            ↓
直接能力证据 + 能力所需知识准备度
            ↓
科研能力画像 + 知识缺口
```

## 2. 为什么不让学生直接报能力分

学生可以报告事实和提交证据，但不能直接提交“Python 90 分”“数值建模 85 分”。能力分必须由统一标准和证据计算得到。这样老师点开任意能力，都能继续展开到课程、专业书、项目任务及核验状态。

## 3. 证据模型

`student_evidence` 绑定 `user_id + resource_id`。资源必须来自第一阶段的标准资源库：

- `course_grade` ↔ `course`
- `book_reading` ↔ `book`
- `project_participation` ↔ `project_task`

课程主要使用成绩与完成度；专业书主要使用阅读完成度与学习深度；科研项目重点使用独立度、成果质量和导师评分。

核验状态及默认可信度：

- `self_reported`：0.72
- `pending`：0.80
- `verified`：1.00
- `rejected`：0.12

## 4. 个人知识分

每条证据先计算个人证据有效度，再通过对应 `resource_knowledge_links` 生成知识贡献：

```text
知识贡献
= 标准覆盖等级 / 5
× 标准权重
× 标准证据强度
× 个人证据有效度
× 核验可信度
```

多个证据使用 `1 - Π(1-contribution)` 合并，既允许多证据增加可信度，又避免简单相加造成分数膨胀。

## 5. 个人能力分

每项科研能力拆成：

- `direct_evidence_score`：课程/项目等直接对该能力的证据；
- `knowledge_readiness_score`：能力所需知识节点当前满足程度；
- `score`：综合能力分。

有直接证据时：

```text
综合能力 = 0.72 × 直接证据 + 0.28 × 知识准备度
```

没有直接证据时：

```text
综合能力 = 0.45 × 知识准备度
```

因此仅仅“学过知识”不会被系统推断成高水平独立科研能力。

## 6. 知识缺口

系统从当前已经形成的能力链路向下检查 `requires` 型知识要求。若当前知识准备度低于阈值，则形成缺口，并优先推荐标准库中尚未形成个人证据的课程、书籍或项目任务。

第二阶段只做“个人能力链路中的缺口”。第三阶段项目匹配上线后，会进一步计算：

```text
项目目标能力 - 当前个人能力 = 项目定向能力缺口
```

## 7. 老师评判

管理员/老师可查看学生，直接对待核验证据填写导师评分、成果质量和核验说明。核验后画像即时重算。学生不能查看别人的个人画像。

## 8. API

新增：

- `GET /api/research-profile/profile`
- `GET /api/research-profile/profile?user_id=N`（管理员/老师）
- `GET /api/research-profile/evidence`
- `POST /api/research-profile/evidence`
- `PATCH /api/research-profile/evidence/{id}/verify`
- `GET /api/research-profile/users`（管理员/老师）

## 9. 下一阶段边界

第三阶段不再修改个人能力评分的底层语义，而是在当前个人画像之上新增：

- 项目需求能力模型；
- 项目 → 学生匹配率；
- 缺口解释；
- 多人科研团队组合；
- 后续再复用同一算法做选课与教师科研方向补知识。
